### **1. AOP Key Concepts Ko Samjhein (Ghar Baith Ke)**  
#### **a. Aspect**  
- **Kya Hai?** Ek "module" jo ek specific kaam karta hai (jaise logging, security).  
- **Real-Life Example:**  
  *Socho aapka ghar ka "Chowkidar" jo har entry/exit pe check karta hai. Woh ek Aspect hai.*  

#### **b. Join Point**  
- **Kya Hai?** Kisi bhi method ka execution point (jaise method call, exception throw).  
- **Real-Life Example:**  
  *Jaise aapka dost aapko call kare, ye ek Join Point hai. Aap call receive kar sakte hain ya ignore.*  

#### **c. Advice**  
- **Kya Hai?** Wo action jo aap Join Point par karte hain.  
- **Types:**  
  - `@Before`: Call karne se pehle (Jaise dost ko call karne se pehle "Hello" bolna).  
  - `@After`: Call ke baad (Jaise call khatam hone ke baad "Bye" bolna).  

#### **d. Pointcut**  
- **Kya Hai?** Ek expression jo batata hai ki Advice kahan apply hoga.  
- **Example:**  
  *"Mere saare dost jo Delhi se hain, unko call karne se pehle Hello bolna."*  
  → Yahan Pointcut hai `execution(* delhiFriends.*(..))`  

#### **e. Weaving**  
- **Kya Hai?** Aspects ko apne code mein jodne ka process.  
- **Real-Life Example:**  
  *Jaise kapde mein stitching. Aapka code kapda hai, aur Aspects stitching ke taar hain.*

### **2. Pointcut Expression Ko Samjhein** 🔍  
**Syntax:** `execution([ReturnType] [Package].[Class].[Method]([Arguments]))`  

#### **Example 1:**  
```java
@Before("execution(* com.example.service.UserService.*(..))")  
```  
- **Breakdown:**  
  - `*`: Any return type.  
  - `com.example.service`: Package name.  
  - `UserService`: Class name.  
  - `.*`: All methods in the class.  
  - `(..)`: Any number of arguments.  

**Matlab:**  
`UserService` class ke **sabhi methods** ke pehle ye Advice chalega.  

#### **Example 2:**  
```java
@AfterReturning(pointcut = "execution(* com.example.Calculator.add(..))", returning = "result")  
```  
- **Breakdown:**  
  - `Calculator.add`: Only `add()` method.  
  - `returning = "result"`: Method ka result capture karo.  

**Matlab:**  
`Calculator` ki `add()` method successful hone ke baad, `result` ko log karo.

### **3. AOP Mein Advice Ke Types** 🛠️  
#### **a. Before Advice**  
- **Kaam:** Target method se pehle execute hota hai.  
- **Use Case:** Input validate karna, log karna.  

```java
@Before("execution(* com.example.service.UserService.*(..))")  
public void logBeforeMethod() {  
    // Ye code UserService ke har method se PEHLE chalega  
    System.out.println("Before Advice: Method shuru ho raha hai!");  
}  
```

#### **b. After Advice**  
- **Kaam:** Target method ke baad execute hoga (success ya failure dono mein).  
- **Use Case:** Resource cleanup, log karna.  

```java
@After("execution(* com.example.service.UserService.*(..))")  
public void logAfterMethod() {  
    System.out.println("After Advice: Method khatam hua!");  
}  
```

#### **c. AfterReturning Advice**  
- **Kaam:** Method successful return karne ke baad chalega.  
- **Use Case:** Return value log karna.  

```java
@AfterReturning(pointcut = "execution(* com.example.service.Calculator.add(..))", returning = "result")  
public void logResult(Object result) {  
    System.out.println("Result hai: " + result);  
}  
```

#### **d. AfterThrowing Advice**  
- **Kaam:** Method mein exception aane par chalega.  
- **Use Case:** Error log karna.  

```java
@AfterThrowing(pointcut = "execution(* com.example.service.UserService.*(..))", throwing = "ex")  
public void logError(Exception ex) {  
    System.out.println("Error aaya hai: " + ex.getMessage());  
}  
```

#### **e. Around Advice (Sabse Powerful)**  
- **Kaam:** Method ke around chalega (pehle aur baad mein).  
- **Use Case:** Performance measure karna, input/output log karna.  

```java
@Around("execution(* com.example.service.UserService.*(..))")  
public Object aroundAdvice(ProceedingJoinPoint joinPoint) throws Throwable {  
    System.out.println("Around Advice: Method se pehle");  
    Object result = joinPoint.proceed(); // Actual method call  
    System.out.println("Around Advice: Method ke baad");  
    return result;  
}  
```

# Spring AOP (Aspect-Oriented Programming): Beginner's Guide

## 1. Introduction to AOP

Aspect-Oriented Programming (AOP) Spring ka ek powerful feature hai jo "cross-cutting concerns" ko handle karne ki permission deta hai. Simplest terms mein, AOP humein code ke specific parts "intercept" karne deta hai taaki hum unke execution se pehle, baad mein, ya dono mein apna custom logic add kar sakein.

### Cross-Cutting Concerns Kya Hote Hain?

"Cross-cutting concerns" wo logic hai jo application ke multiple parts mein repeat hota hai aur business logic se directly related nahi hota. Examples include:

- **Logging** - Application ke different parts mein operations ka record rakhna
- **Security** - Authorization aur authentication checks
- **Transaction Management** - Database operations ke saath transactions ka management
- **Error Handling** - Global exception handling
- **Performance Monitoring** - Methods ke execution time ko track karna

### AOP Kyu Use Karna Chahiye?

1. **Code Duplication Reduce Karta Hai** - Aapko har method mein same logging/security code likhne ki zarurat nahi
2. **Maintainability Badhata Hai** - All cross-cutting logic ek jagah manage hota hai
3. **Cleaner Business Logic** - Aapka business logic core functionality par focus kar sakta hai
4. **Modular & Reusable Code** - Cross-cutting concerns modular and reusable tarike se implement hote hain

### AOP Ke Core Concepts

AOP ke kuch fundamental concepts ko samajhna zaroori hai:

```
           ┌───────────────────┐
           │      Aspect       │
           │   (LoggingAspect) │
           └───────────────────┘
                     │
                     ▼
     ┌─────────────────────────────┐
     │          Advice             │
     │ (@Before, @After, @Around)  │
     └─────────────────────────────┘
                     │
                     ▼
     ┌─────────────────────────────┐
     │        Join Point           │
     │      (Method Call)          │
     └─────────────────────────────┘
                     │
                     ▼
     ┌─────────────────────────────┐
     │        Pointcut             │
     │  (execution(* service.*(..)))│
     └─────────────────────────────┘
```

1. **Aspect**: Class jisme cross-cutting functionality define hoti hai (e.g., `LoggingAspect.java`)
2. **Advice**: Aspect kya karega aur kab karega (e.g., `@Before`, `@After`, `@Around`)
3. **Join Point**: Program execution ka specific point jahan aspect apply hoga (e.g., method execution)
4. **Pointcut**: Join points ka collection jahan advice apply hoga (e.g., specific methods ya patterns)
5. **Weaving**: Aspects ko target objects ke saath integrate karna

## 3. Basic AOP Implementation

Chaliye ab ek basic AOP implementation ke through jaate hain.

### Step 1: Create an Aspect Class

```java
package com.example.aspect;

import org.aspectj.lang.JoinPoint;
import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.annotation.Before;
import org.springframework.stereotype.Component;

@Aspect           // Ye annotation batata hai ki ye class ek aspect hai
@Component        // Spring container mein register karne ke liye
public class LoggingAspect {

    // Ye advice (@Before) batata hai ki target method se pehle ye method execute hoga
    @Before("execution(* com.example.service.*.*(..))")
    public void logBeforeMethodExecution(JoinPoint joinPoint) {
        // Method ka name get karenge
        String methodName = joinPoint.getSignature().getName();
        
        // Class ka name get karenge
        String className = joinPoint.getTarget().getClass().getSimpleName();
        
        // Log message
        System.out.println("LOGGING: Method " + className + "." + methodName + " execution shuru hone wala hai");
    }
}
```

**Line-by-Line Explanation:**

- `@Aspect` - Ye annotation Spring ko batata hai ki ye class AOP aspect hai
- `@Component` - Spring ke context mein is class ka bean register karta hai
- `@Before` - Method execution se pehle advice execute karne ke liye
- `execution(* com.example.service.*.*(..))` - Pointcut expression hai jo:
  - `*` - Koi bhi return type
  - `com.example.service` - Is package mein
  - `*` - Koi bhi class
  - `*` - Koi bhi method
  - `(..)` - Koi bhi arguments
- `JoinPoint` - Method details provide karta hai (name, arguments, etc.)

## 4. Different Types of Advice

Spring AOP 5 types ke advice provide karta hai, jo aapko method execution ke different points par intercept karne ki permission dete hain:

### 1. @Before Advice

Method execution se pehle chalta hai. Hum iska use validation, logging, ya access checks ke liye kar sakte hain.

```java
@Before("execution(* com.example.service.*.*(..))")
public void beforeAdvice(JoinPoint joinPoint) {
    System.out.println("Method se pehle execute ho raha hai: " + joinPoint.getSignature().getName());
    // Method ke arguments access karne ke liye
    Object[] args = joinPoint.getArgs();
    for (Object arg : args) {
        System.out.println("Argument: " + arg);
    }
}
```

### 2. @After Advice

Method execution ke baad chalta hai, chahe method successfully complete ho ya exception throw kare.

```java
@After("execution(* com.example.service.*.*(..))")
public void afterAdvice(JoinPoint joinPoint) {
    System.out.println("Method ke baad execute ho raha hai: " + joinPoint.getSignature().getName());
    // Clean up code yahan likha ja sakta hai
}
```

### 3. @AfterReturning Advice

Method successfully return karne ke baad chalta hai. Return value ko access kar sakte hain.

```java
@AfterReturning(pointcut = "execution(* com.example.service.*.*(..))", returning = "result")
public void afterReturningAdvice(JoinPoint joinPoint, Object result) {
    System.out.println("Method successfully execute hua: " + joinPoint.getSignature().getName());
    System.out.println("Result mila: " + result);
    // Result ko modify bhi kar sakte hain (lekin immutable objects mein nahi)
}
```

### 4. @AfterThrowing Advice

Method exception throw karne par chalta hai. Exception details ko access kar sakte hain.

```java
@AfterThrowing(pointcut = "execution(* com.example.service.*.*(..))", throwing = "ex")
public void afterThrowingAdvice(JoinPoint joinPoint, Exception ex) {
    System.out.println("Method ne exception throw kiya: " + joinPoint.getSignature().getName());
    System.out.println("Exception: " + ex.getMessage());
    // Exception logging ya handling yahan kar sakte hain
}
```

### 5. @Around Advice

Sabse powerful advice hai jo method execution ko completely wrap karta hai. Method execution se pehle aur baad mein code run kar sakta hai, return value modify kar sakta hai, exceptions handle kar sakta hai, ya method execution ko completely skip bhi kar sakta hai.

```java
@Around("execution(* com.example.service.*.*(..))")
public Object aroundAdvice(ProceedingJoinPoint joinPoint) throws Throwable {
    System.out.println("Method execution se pehle: " + joinPoint.getSignature().getName());
    
    // Method start time
    long startTime = System.currentTimeMillis();
    
    // Method ko proceed karayen
    Object result = null;
    try {
        // Original method ko call karne ke liye
        result = joinPoint.proceed();
        
        // Result ko modify karne ka option hai
        // result = "Modified " + result; // Agar return type String hai to
    } catch (Exception e) {
        // Exception handling
        System.out.println("Exception caught: " + e.getMessage());
        throw e; // Re-throw or handle
    }
    
    // Method end time
    long endTime = System.currentTimeMillis();
    
    System.out.println("Method execution ke baad: " + joinPoint.getSignature().getName());
    System.out.println("Method ne " + (endTime - startTime) + "ms liye");
    
    return result;
}
```

**Important Notes about @Around:**
- `ProceedingJoinPoint` use karna zaroori hai (normal JoinPoint nahi)
- Target method ko execute karne ke liye `proceed()` method call karna zaroori hai
- Original method ke return value ko modify kar sakte hain ya completely replace kar sakte hain
- Exceptions handle kar sakte hain
- Agar proceed() call na karo, toh original method execute hi nahi hoga

## 5. Advanced Pointcut Expressions

Pointcut expressions kis method par advice apply hoga, ye specify karne ke liye use hote hain. Yeh AspectJ pointcut expression language ka use karte hain.

### Common Pointcut Patterns

1. **Package Specific Methods**
```java
// com.example.service package ke saare methods
@Before("execution(* com.example.service.*.*(..))")
```

2. **Specific Return Type**
```java
// Sirf String return karne wale methods
@Before("execution(String com.example.service.*.*(..))")
```

3. **Specific Method Name**
```java
// 'get' se shuru hone wale methods
@Before("execution(* com.example.service.*.get*(..))")
```

4. **Specific Parameters**
```java
// Exactly ek String parameter lene wale methods
@Before("execution(* com.example.service.*.*(String))")

// Koi bhi number of parameters
@Before("execution(* com.example.service.*.*(..))")

// No parameters
@Before("execution(* com.example.service.*.*())")
```

5. **Method Visibility**
```java
// Sirf public methods
@Before("execution(public * com.example.service.*.*(..))")
```

### Reusable Pointcuts

Aap reusable pointcuts define kar sakte hain:

```java
@Pointcut("execution(* com.example.service.*.*(..))")
public void serviceLayer() {}

@Pointcut("execution(* com.example.repository.*.*(..))")
public void dataAccessLayer() {}

// In pointcut ko combine karna
@Pointcut("serviceLayer() || dataAccessLayer()")
public void applicationFlow() {}

// Use combined pointcut
@Before("applicationFlow()")
public void logApplicationFlow(JoinPoint joinPoint) {
    // Logging logic
}
```

## 6. Real-World Example: Security Aspect

Chaliye ek real-world example dekhte hain - ek security aspect jo methods execute hone se pehle authorization check karta hai:

```java
package com.example.aspect;

import com.example.annotation.RequiresRole;
import com.example.security.SecurityContext;
import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.annotation.Aspect;
import org.aspectj.lang.reflect.MethodSignature;
import org.springframework.stereotype.Component;

import java.lang.reflect.Method;

@Aspect
@Component
public class SecurityAspect {

    private final SecurityContext securityContext;

    public SecurityAspect(SecurityContext securityContext) {
        this.securityContext = securityContext;
    }

    @Around("@annotation(com.example.annotation.RequiresRole)")
    public Object enforceRoleBasedSecurity(ProceedingJoinPoint joinPoint) throws Throwable {
        // Method annotation ko access karna
        MethodSignature signature = (MethodSignature) joinPoint.getSignature();
        Method method = signature.getMethod();
        
        // Annotation ka value extract karna
        RequiresRole annotation = method.getAnnotation(RequiresRole.class);
        String requiredRole = annotation.value();
        
        // Current user ke roles ko check karna
        if (securityContext.isUserInRole(requiredRole)) {
            // User ko required role hai, method ko execute hone den
            return joinPoint.proceed();
        } else {
            // Access denied
            throw new SecurityException("Access denied! Role '" + requiredRole + "' required.");
        }
    }
}
```

## 7. Best Practices for Using AOP

1. **Don't Overuse AOP**
   - AOP sirf cross-cutting concerns ke liye use karein, business logic ke liye nahi
   - Har cheez ke liye aspect create na karein, sirf wo logic jo multiple jagah repeat hota hai

2. **Readable Pointcuts**
   - Complex pointcut expressions ko named pointcuts mein break karein
   - Documentation add karein taaki dusre developers samajh sakein kya ho raha hai

3. **Performance Considerations**
   - @Around advice most powerful hai, lekin agar sirf @Before ya @After ki zarurat hai to wahi use karein
   - Too many aspects can slow down application startup

4. **Testing**
   - Aspects ko test karna challenging ho sakta hai
   - Unit tests mein mock aspects create karein ya real aspects ko include karein

5. **Exception Handling**
   - @Around advice mein exceptions handle karte waqt careful rahein
   - Original exceptions ko suppress na karein jab tak deliberately na karna ho

6. **Avoid state in aspects**
   - Aspects should generally be stateless
   - If state is needed, consider thread-safety

### Logging Aspect

```java
@Aspect
@Component
public class LoggingAspect {
    
    private final Logger logger = LoggerFactory.getLogger(LoggingAspect.class);
    
    @Around("execution(* com.example.service.*.*(..))")
    public Object logMethodExecution(ProceedingJoinPoint joinPoint) throws Throwable {
        String methodName = joinPoint.getSignature().getName();
        String className = joinPoint.getTarget().getClass().getSimpleName();
        
        logger.info("Executing {}::{} with parameters: {}", 
                className, methodName, Arrays.toString(joinPoint.getArgs()));
        
        try {
            Object result = joinPoint.proceed();
            logger.info("{}::{} executed successfully with return value: {}", 
                    className, methodName, result);
            return result;
        } catch (Exception e) {
            logger.error("{}::{} threw exception: {}", 
                    className, methodName, e.getMessage());
            throw e;
        }
    }
}
```

### Performance Monitoring Aspect

```java
@Aspect
@Component
public class PerformanceMonitoringAspect {
    
    private final Logger logger = LoggerFactory.getLogger(PerformanceMonitoringAspect.class);
    
    @Around("execution(* com.example.service.*.*(..))")
    public Object monitorMethodPerformance(ProceedingJoinPoint joinPoint) throws Throwable {
        long startTime = System.currentTimeMillis();
        
        try {
            return joinPoint.proceed();
        } finally {
            long executionTime = System.currentTimeMillis() - startTime;
            String methodName = joinPoint.getSignature().getName();
            
            if (executionTime > 500) {  // More than 500ms is slow
                logger.warn("SLOW METHOD: {} took {}ms to execute", 
                        methodName, executionTime);
            } else {
                logger.debug("METHOD TIMING: {} took {}ms to execute", 
                        methodName, executionTime);
            }
        }
    }
}
```

### Transaction Management (Spring already provides this)

```java
@Aspect
@Component
public class TransactionAspect {
    
    private final PlatformTransactionManager transactionManager;
    
    public TransactionAspect(PlatformTransactionManager transactionManager) {
        this.transactionManager = transactionManager;
    }
    
    @Around("@annotation(com.example.annotation.Transactional)")
    public Object manageTransaction(ProceedingJoinPoint joinPoint) throws Throwable {
        TransactionStatus status = transactionManager.getTransaction(new DefaultTransactionDefinition());
        
        try {
            Object result = joinPoint.proceed();
            transactionManager.commit(status);
            return result;
        } catch (Exception e) {
            transactionManager.rollback(status);
            throw e;
        }
    }
}
```

## 9. Common Interview Questions and Answers

### 1. What is AOP and how does it differ from OOP?

**Answer:** AOP (Aspect-Oriented Programming) ek programming paradigm hai jo cross-cutting concerns ko modular tarike se handle karne mein help karta hai. OOP (Object-Oriented Programming) mein, code ko classes aur objects mein organize kiya jata hai. Lekin kuch functionality (like logging, security) multiple classes mein spread ho jati hai.

AOP aise cross-cutting concerns ko separate aspects mein extract karne ki permission deta hai. Ye code duplication reduce karta hai aur maintainability improve karta hai, kyunki har class mein logging/security code repeat karne ki zarurat nahi hoti.

### 2. What are the core concepts of AOP in Spring?

**Answer:**
- **Aspect:** Cross-cutting concern ko implement karne wali class (e.g., LoggingAspect)
- **Advice:** Aspect kya action perform karega aur kab (e.g., @Before, @After)
- **Pointcut:** Kis jagah advice apply hoga ye specify karta hai
- **Join Point:** Program execution ka specific point jahan aspect trigger hoga
- **Weaving:** Aspect code ko target object ke saath integrate karna

### 3. What is the difference between Spring AOP and AspectJ?

**Answer:**
- **Spring AOP:**
  - Lightweight, Spring container ke saath integrate hai
  - Proxy-based implementation (runtime weaving)
  - Sirf method execution join points support karta hai
  - Setup simple hai lekin limited capabilities hai

- **AspectJ:**
  - Complete AOP solution with full AOP capabilities
  - Compile-time ya load-time weaving support
  - All join points support karta hai (method calls, field access, etc.)
  - More powerful but more complex to set up

Spring AOP actually uses AspectJ's annotation style aur pointcut expression language, lekin implementation different hai.

### 4. What are the different types of advice in Spring AOP?

**Answer:**
- **@Before:** Method execution se pehle
- **@After:** Method execution ke baad (success or exception)
- **@AfterReturning:** Method successfully return karne ke baad
- **@AfterThrowing:** Method exception throw karne par
- **@Around:** Method execution ke pehle aur baad, most powerful advice

### 5. What is a ProceedingJoinPoint?

**Answer:** ProceedingJoinPoint @Around advice mein use hota hai. Isse aap:
- Target method ko manually execute kar sakte hain (proceed() method ke through)
- Method arguments ko access aur modify kar sakte hain
- Original method ko skip kar sakte hain ya conditional execution kar sakte hain
- Return value ko modify kar sakte hain

Ye normal JoinPoint ka extension hai with added ability to control method execution.

### 6. How do you create custom annotations for AOP?

**Answer:** Custom annotations create karne ke liye:

1. Annotation define karein:
```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface LogExecutionTime {
}
```

2. Pointcut expression mein annotation ka use karein:
```java
@Around("@annotation(com.example.annotation.LogExecutionTime)")
public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
    // Implementation
}
```

### 7. What are the limitations of Spring AOP?

**Answer:**
- Sirf public method execution join points support karta hai
- Self-invocation par aspects trigger nahi hote (jab same class ke andar ek method dusre ko call kare)
- Spring beans par hi applicable hai, normal Java classes par nahi
- Limited pointcut expressions compared to full AspectJ
- Proxy-based implementation ke performance implications ho sakte hain

### 8. How does Spring AOP implement its proxy mechanism?

**Answer:** Spring AOP two types ke proxies use karta hai:

1. **JDK Dynamic Proxies:** By default, interfaces implement karne wale beans ke liye. Interface methods ko intercept karta hai.

2. **CGLIB Proxies:** Jab target class koi interface implement nahi karta ya proxy-target-class=true set hai. Class inheritance ka use karke subclass create karta hai.

Proxy objects target bean ke method calls ko intercept karte hain aur appropriate advice execute karte hain before/after forwarding the call to the actual target.

**Task:** Ek REST API application banaye jisme @LogApiCall naam ka custom annotation ho. Jab bhi koi controller method is annotation se annotate ho, to uska API call logging ho with request details.

**Step 2:** Aspect Create Karein

```java
package com.example.aspect;

import com.example.annotation.LogApiCall;
import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.annotation.Aspect;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Component;
import org.springframework.web.context.request.RequestContextHolder;
import org.springframework.web.context.request.ServletRequestAttributes;

import jakarta.servlet.http.HttpServletRequest;

@Aspect
@Component
public class ApiLoggingAspect {

    private static final Logger logger = LoggerFactory.getLogger(ApiLoggingAspect.class);

    @Around("@annotation(logApiCall)")
    public Object logApiCall(ProceedingJoinPoint joinPoint, LogApiCall logApiCall) throws Throwable {
        HttpServletRequest request = ((ServletRequestAttributes) RequestContextHolder.getRequestAttributes()).getRequest();
        
        // Request details
        String method = request.getMethod();
        String uri = request.getRequestURI();
        String params = request.getQueryString() != null ? request.getQueryString() : "";
        String clientIP = request.getRemoteAddr();
        
        // Log pre-execution
        logger.info("API CALL START: {} {} from IP: {}, Query: {}", method, uri, clientIP, params);
        
        long startTime = System.currentTimeMillis();
        Object result = null;
        
        try {
            // Execute the method
            result = joinPoint.proceed();
            return result;
        } catch (Exception e) {
            logger.error("API CALL EXCEPTION: {} {}, Error: {}", method, uri, e.getMessage());
            throw e;
        } finally {
            long duration = System.currentTimeMillis() - startTime;
            logger.info("API CALL END: {} {} completed in {}ms with status: {}", 
                    method, uri, duration, 
                    result != null ? "SUCCESS" : "FAILURE");
        }
    }
}
```

**Step 3:** REST Controller Create Karein

```java
package com.example.controller;

import com.example.annotation.LogApiCall;
import com.example.model.User;
import org.springframework.web.bind.annotation.*;

import java.util.ArrayList;
import java.util.List;

@RestController
@RequestMapping("/api/users")
public class UserController {

    private List<User> users = new ArrayList<>();

    @LogApiCall
    @GetMapping
    public List<User> getAllUsers() {
        return users;
    }

    @LogApiCall
    @PostMapping
    public User createUser(@RequestBody User user) {
        users.add(user);
        return user;
    }

    @LogApiCall
    @GetMapping("/{id}")
    public User getUserById(@PathVariable Long id) {
        return users.stream()
                .filter(user -> user.getId().equals(id))
                .findFirst()
                .orElseThrow(() -> new RuntimeException("User not found"));
    }

    // This method doesn't have @LogApiCall annotation, so won't be logged
    @DeleteMapping("/{id}")
    public void deleteUser(@PathVariable Long id) {
        users.removeIf(user -> user.getId().equals(id));
    }
}
```

## 11. Conclusion

Spring AOP ek powerful tool hai jo aapko cross-cutting concerns ko modular tarike se implement karne ki permission deta hai. Ismein thodi learning curve ho sakti hai, lekin benefits significant hain - especially large applications mein where logging, security, and performance monitoring jaise concerns important hote hain.

Key points jo yaad rakhne chahiye:
- AOP sirf cross-cutting concerns ke liye use karein
- Start with simple aspects aur gradually more complex patterns adopt karein
- Pointcut expressions ko carefully define karein to target exactly what you need
- Documentation aur readable code par focus karein
- Be aware of limitations compared to full AspectJ

Happy aspect weaving!
